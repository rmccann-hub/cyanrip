# cyanrip (fork)

CD-ripping tool written in C (meson build), linking FFmpeg (libavcodec/libavformat/
libavfilter/libavutil/libswresample) and libcdio-paranoia. This is a personal fork
of upstream cyanreg/cyanrip; upstream has no CONTRIBUTING.md/CODE_OF_CONDUCT.md, so
there's no external convention doc to defer to beyond what's below.

## Build

    meson setup build
    ninja -C build
    meson test -C build --print-errorlogs

If setup fails on missing dependencies, it's almost always a missing `-dev`
package, not a real bug. On Debian/Ubuntu the full set:

    apt-get install -y meson ninja-build pkg-config \
      libavcodec-dev libavformat-dev libavfilter-dev libavutil-dev \
      libswresample-dev libcdio-dev libcdio-paranoia-dev \
      libmusicbrainz5-dev libcurl4-openssl-dev

Minimum versions are pinned in `src/meson.build` (e.g. libavcodec >= 59.24.100).
Check `meson setup build`'s dependency-resolution errors first before assuming
code is broken. Version banner is `cyanrip --version` / `-v`, not `-V`.

## Where things live

- `src/cyanrip_main.c` -- CLI arg parsing, disc/track enumeration, and the main
  rip loop (`cyanrip_rip_track()`, the `-Z` repeat/converge logic lives here);
  pregap-action selection (`CYANRIP_PREGAP_DEFAULT/DROP/MERGE/TRACK`) also lives
  here.
- `src/cyanrip_encode.c` -- FFmpeg encode/filter graph: decode -> filter
  (deemphasis, ebur128 peak/loudness, etc.) -> encode -> mux per output format.
- `src/cyanrip_log.c` -- rip log and human-readable report writer.
- `src/cue_writer.c` -- CUE sheet writer; owns `INDEX 00`/`PREGAP` emission for
  dropped/merged/track-per-pregap handling.
- `src/naming.c`, `src/musicbrainz.c`, `src/coverart.c`, `src/accurip.c`,
  `src/discid.c` -- naming-scheme expansion, MusicBrainz lookups, cover art,
  AccurateRip checksums, disc ID, respectively.
- `tests/` -- meson-driven unit tests (`fun512.c`, `naming.c`) plus disc-image
  integration tests (`rip_images.py` against BIN/CUE and NRG fixtures in
  `tests/fixtures/`, generated by `gen_fixtures.py`).

## No physical CD drive in this environment

Sessions here are sandboxed cloud containers with **no CD-ROM drive attached**
(no `/dev/sr0`). `meson test -C build` still exercises the full rip pipeline
end-to-end because `tests/rip_images.py` rips synthetic BIN/CUE and NRG disc
*images* via `-d <image>` (libcdio's own image driver), not a real drive -- so
build/log-format/CRC verification all work fully in-session by ripping
`tests/fixtures/*.cue`/`cdda.nrg` directly with the built binary. What can't
be verified here: real drive behavior (offset autodetection `-f`, MMC/
subchannel quirks, paranoia error-correction on damaged media). Flag any
change touching drive I/O as "needs verification on real hardware" and defer
that check to the user's own machine.

## Code style

- Matches existing code: K&R-ish C, 4-space indentation, no tabs, `c99`
  (`meson.build`: `c_std=c99`, `warning_level=1`,
  `-Werror=implicit-function-declaration`).
- Every source file starts with the LGPL-2.1+ header block (copy it verbatim
  from an existing file such as `src/utils.c` for new files).
- No CODING_STYLE doc exists upstream or in this fork -- match the nearest
  existing file/function rather than inventing a new convention. Log lines in
  particular follow tight column-aligned label:value formatting within each
  block (see `cyanrip_log_track_end()`); read a few neighboring lines before
  adding one.
- Upstream commit style: plain, imperative/descriptive subject lines, no
  conventional-commits prefixes (e.g. "Fix handling of no pregap for merged
  pregap tracks in cue writer"). One logical change per commit.
