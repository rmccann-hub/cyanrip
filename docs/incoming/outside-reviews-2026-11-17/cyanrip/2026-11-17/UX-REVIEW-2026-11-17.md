# UX review: cyanrip `platterpus-fork`, 2026-11-17

Checkout: `fd20a0a` (`platterpus-fork`), version `0.9.4-rc3+platterpus.34`. One evaluator (an
agent), two passes: the first rip, then each message and option. Severity uses Nielsen's 0 to 4
scale, as `usability-review` uses it.

**What ran.** It built in a scratch tree, with the build headers from Ubuntu 24.04's `-dev` packages
unpacked into
`/tmp/claude-0/-home-user-claude-code-skills/46cfbc1a-d1c5-5a09-bbbb-4b2444266d0f/scratchpad/ux/cyanrip-deps/root`
(not installed system-wide), Meson in a venv there, and the build in `.../scratchpad/ux/cyanrip-build2`.
To run, it needs `LD_LIBRARY_PATH` set to that root's `usr/lib/x86_64-linux-gnu`. No CD drive
was available. Rips used the repository's own CUE/BIN fixtures (`tests/fixtures/basic.cue`
with `cdda.bin` copied to `basic.bin`), which do read, encode and log as a real rip does. Not
run: a real drive (offset refusal, permission errors, stalls, C2), Ctrl-C mid-rip (the image
rips in 0.06 s), the QR code (built without libqrencode). Those findings come from the source.

**Evidence base** (abbreviated `OUT/` below):
`/tmp/claude-0/-home-user-claude-code-skills/46cfbc1a-d1c5-5a09-bbbb-4b2444266d0f/scratchpad/ux/cyanrip-out/`.
Screenshots are of captured output rendered at 80 columns: `OUT/shots/help.png`,
`OUT/shots/first-run.png`, `OUT/shots/unknown-disc.png`, `OUT/shots/rip-head.png`. Raw
captures: `OUT/rip1.stdout` (rip with `-N -o flac,mp3`), `OUT/info.stdout` (`-I`),
`OUT/rip3.out` (rip of an unknown disc), `OUT/noDrive.txt` (no-drive and bad-argument runs).

**Contract tags.** Every finding says what a fix does to Platterpus's parser:
- **[Safe]**: no stable line, routing or exit code changes, and Platterpus doesn't match the text.
- **[Additive]**: adds a new line. `PROVIDER-CONTRACT.md` P2 allows nothing new silently, and
  Platterpus records an unknown line as `unrecognised` (`platterpus/src/platterpus/parsers/cyanrip_log.py:250`),
  so it needs an announcement but breaks nothing.
- **[Contract]**: rewords a P2/P5 line, moves output between streams or changes an exit code.
  That needs a handshake round. Platterpus keeps exact error texts in
  `src/platterpus/ripper_message_inventory.py` (`Offset is unset!` at :841), and it reads
  **stdout** only (`workers/rip_worker.py:5`).

One general point: P3 calls the progress line "unstable wording", but Platterpus parses it by
regex (`workers/rip_worker.py:243`, `inbound_text.py:175`). The contract understates that
dependency, so treat the progress line as [Contract] too.

## 2. Findings by area

### First run and onboarding

**F1. No drive, or a wrong drive: no cause, no next step.** Sev 3. Heuristic 9 (recognize,
diagnose, recover); `error-responses` rule 6. [Contract] for the reword, [Additive] for a hint,
[Safe] for the libcdio lines (P3 says `libcdio %s: %s` is unstable, and Platterpus doesn't
match it).
Evidence (`OUT/shots/first-run.png`):
```
$ cyanrip
No device specified and unable to get default device!
$ cyanrip -d /dev/sr0
libcdio warning: Can't get file status for /dev/sr0:<U+000A>No such file or directory
libcdio warning: could not retrieve file info for `/dev/sr0': No such file or directory
libcdio warning: can't open nrg image file /dev/sr0 for reading
Unable to open device: /dev/sr0
```
A person can't tell whether there's no drive, no disc, or no permission (on Linux, usually the
`cdrom` group). The library's three lines are about image formats they never asked for, and
the `<U+000A>` is the log's newline escape leaking into a terminal line. Fix: keep the P2 line
and follow it with a new line, such as `No CD drive found. Connect one, or name it with -d
(for example -d /dev/sr0).` For an open failure, give the errno text and, for `EACCES`, the
group hint. Show libcdio's lines only in the log, or once under one heading, with the trailing
newline trimmed before escaping instead of escaped. Effort S.

**F2. An unknown disc aborts the first rip and is counted as a ripping error.** Sev 3.
Heuristic 9; `usability-review` "a verdict over a failure". [Contract] for the count and the
reword; [Safe] for `-N` behavior advice in the README.
Evidence (`OUT/shots/unknown-disc.png`, exit 1):
```
Unable to find release info for this CD, and metadata hasn't been manually added!
Please help improve the MusicBrainz DB by submitting the disc info via the following URL:
https://musicbrainz.org/cdtoc/attach?toc=...
To continue add metadata via -a or -t, or ignore via -N!
...
Ripping errors: 1
Rip completed:  no (aborted, 0 of 2 tracks)
```
Home-burned and obscure discs, a large share of what people rip at home, fail before reading
a sector. `Ripping errors: 1` tells them something went wrong with the disc. The fork already
fixed this for two other refusals: `cyanrip_main.c:4043` says a refusal to start is
`fatal_abort`, "and nothing failed to read". `cyanrip_main.c:4142` still does
`total_error_count++`. Fix: make it `fatal_abort` with `CRIP_EXIT_USAGE`, as `Offset is
unset!` is. Lead with the action: `This disc isn't on MusicBrainz. Rip without tags with -N,
or add tags with -a and -t.` The URL follows as an invitation. Effort S.

**F3. `Offset is unset!` without a way to find the offset or keep it.** Sev 3, from the
source (no drive here). Heuristics 9 and 7 (flexibility). [Contract] for the reword (it's in
Platterpus's inventory), [Additive] for a hint line, [Safe] for a config value.
Evidence: `cyanrip_main.c:4055`, `Offset is unset! To continue with an offset of 0, run with
-s 0!`. The README says so too (`README.md:145`), but `--help` says `--offset (-s): CD drive
offset in samples (default: 0)`, so the help names a default that the program then refuses.
Fix: add a line after it: `Find your drive's offset with -f (needs a disc AccurateRip knows),
then pass it with -s.` In help, drop `(default: 0)` and say "required on a drive". Then accept
the offset from an environment variable or a config file keyed by the drive's model, so it's
typed once. Effort S for the hint and help, M for config.

**F4. README first screen.** Sev 2. `house-style` writing-style; heuristic 8 (minimalist).
[Safe].
Evidence: `README.md:3` gives one sentence of what it does, then 13 lines (`:5-17`) on SemVer
build metadata, `release_seq` and the handshake directory. The example version in it is stale
(`0.9.4-rc2+platterpus.14`; this build is `rc3+platterpus.34`), which it admits. There's no
first-rip example anywhere in the README (searching for `cyanrip -` finds only `cyanrip -I`
at `:343`). Installation (`:38-102`) lists eight package managers that install upstream, not
this fork (the notice at `:40` says so). Compiling (`:118`) says the dependencies "are
available on any up-to-date Linux distribution" without package names. I needed nine `-dev`
packages to build on Ubuntu 24.04. Fix: after the tagline, put a three-command quick start
(`cyanrip -f`, `cyanrip -s <offset>`, `cyanrip -N` for unknown discs). Shrink the notice to two
lines ("A fork for Platterpus; see Fork differences") and move the versioning text into Fork
differences. List the Debian/Fedora package names under Compiling. Effort S.

### The main screen: run output

**F5. Internal process state and dense diagnostics in every header.** Sev 2. Heuristic 2
(match the real world); `usability-review` labels. [Contract] (P2: `Handshake:`,
`Consumer:`, `Pregap search:` are stable lines Platterpus reads).
Evidence (`OUT/shots/rip-head.png`):
`Handshake: round 41 lap 3 OPEN, verdict OPEN -- NOT a released build`. "NOT a released build"
in capitals on a build someone was given reads as a warning they can't act on.
`Consumer: not identified (no --consumer given)` suggests they did something wrong.
`track 2: 1 sectors asked; 0 reads failed the CRC; 0 sectors gave no frame passing it; 0 frames
were another sector's; 0 had no address; frames answer +0 sectors off; LSN 1 to 299 undecided`.
`Drive used: none (disc image, read by libcdio's CDRWIN driver, revision 2.1.)` ends in a
doubled period from libcdio's string. Fix, without touching the log: these lines belong in the
log, which Platterpus reads. A terminal mode (stdout is a terminal and no `--consumer`) could
print a short header to the screen and keep the full block for the file. That's a routing
change on stdout, so it needs a round. If it's agreed, Platterpus loses nothing, since it
always passes `--consumer`. Effort M.

**F6. The loudness figures are printed twice, once in FFmpeg's words.** Sev 1. Heuristic 8.
[Contract] for removing libavfilter's block from stdout (P3 marks it "not ours", and
Platterpus prefers the P2 rows).
Evidence: `OUT/rip1.stdout`, a `Summary: / Integrated loudness: / I: -8.7 LUFS ...` block (16
lines) per track, followed by `Integrated loudness (R128): -8.7 LUFS`, and again at album
level. Fix: send the ebur128 filter's own log to the logfile only, or drop it. Effort S.

**F7. Album loudness shown when nothing was measured.** Sev 2. `usability-review` "a value
shown before it's measured". [Contract] (P2 `cyanrip_encode.c:1076`, ungated).
Evidence: `cyanrip/docs/sample-interrupted.log`, an interrupted run with `0 of 3 tracks`
prints `Album integrated loudness (R128): -70.0 LUFS` and peaks of `0.0 dBFS`. -70 LUFS is
the ebur128 floor, not a reading. Fix: print `not measured (no track completed)`, as the
per-track rows are gated. Effort S, with a round.

**F8. The end of a rip doesn't say where the files went.** Sev 1. Heuristic 1 (visibility).
[Additive].
Evidence: `OUT/rip1.stdout` ends `Rip completed: yes (2 of 2 tracks)` / `Ripping finished at
...`; the folders appear only inside each track's `File(s):` block, long scrolled off. `-I`
prints `Log(s) will be written to:` but a real rip doesn't (`cyanrip_main.c:4277` is in the
`-I` branch only). Fix: one `Output folder:` line per format, at the start and the end.
Effort S.

### Wording and consistency

**F9. Expected conditions written as failures, with exclamation marks.** Sev 2. Heuristic 9;
`error-responses` "Messages for people". [Contract] (P2 lines).
Evidence: `OUT/rip6/o.txt`, a successful rip with defaults and `-N` prints `No MusicBrainz
release ID at cover art lookup, cannot search Cover Art DB!` (the person asked for no
MusicBrainz) and `Unable to get AccuRIP DB data: missing entry!` (the disc isn't in the
database, which is normal). About 150 of the ~170 error strings in P5 end in `!`. Fix: say
these two plainly or skip them: `Cover art: skipped (no MusicBrainz release)`, `AccurateRip:
this disc isn't in the database`. The header's `AccurateRip: not found` already says the
second. Effort S.

**F10. One database under four spellings.** Sev 2. `usability-review` "labels disagree".
[Contract] for P2 lines; [Safe] for help and README.
Evidence: `AccurateRip` (header, `--prefer-accuraterip-match`), `AccuRIP DB` (`accurip.c:362`),
`Accurip` (track block, `--no-accurip`), `AccuRip` (`--find-offset` help, `README.md:205`).
Also `Cover art DB` beside `Cover Art Archive`, and `Misc. options`. Fix: "AccurateRip"
everywhere a person reads it; keep flag names. Effort S for help and README, M with the log.

**F11. The fork's additions are consistent in grammar, longer in style.** Sev 1.
Heuristic 4 (consistency). [Safe] for help, [Contract] for the messages.
Upstream's help lines are short phrases (`Set drive speed`). The fork's are sentences of
30-50 words: `--reread-until-accuraterip: Under -Z, read on past an agreement AccurateRip does
not match, on a track it holds at this confidence or more, until a read it matches at this
confidence or a limit`. The fork's errors are better than upstream's because they say why
and what to do (`--keep-every-read needs -Z: it saves -Z's reads, and without -Z there is one
read, the output!`), but they keep upstream's `!`. Fix: help lines of about 60 characters, the
detail in the README table, which already has it. Effort S.

### Layout and type (terminal)

**F12. Help.** Sev 2. `command-line-interfaces` rules 1-2, clig.dev "lead with examples".
[Contract-adjacent]: P1 of the contract is generated from `--help`, so changing help
regenerates P1 and is a round in practice.
Evidence: `OUT/shots/help.png`. The widest line is 215 columns, and 40 of 60 lines wrap at 80.
No `Usage:` line, no example. `(default: false)` on 19 switches. `--bitrate (-b): ... (default:
256.000000)` (`genopt.h:412`, `%f`). `--version (-v): Print the version number (-V accepted as
an alias)`. The four scheme defaults, like `{album}{if #releasecomment# > #0#
(|releasecomment|)} [{format}]`, are unreadable without the README's syntax section and give
no pointer to it. `--speed (-S): (default: 0)` while the README says "unset, usually maximum".
`--reread-time-limit (default: 0)` but 0 is refused (`[1:2147483647]`). Fix: a usage line and
two examples at the top; wrap descriptions to the terminal width (80 when it's not a
terminal); drop `(default: false)`; format the bitrate as `%g`; end with "Naming schemes and
more: see the README". Effort M.

**F13. No color, which is fine; the QR code ignores the opt-outs.** Sev 1.
`command-line-interfaces` rule 5. [Safe]. `qrcode.c:123` checks only `isatty(stdout)`, not
`NO_COLOR` or `TERM=dumb`, before writing 256-color escapes. Fix: rule 5's four checks.
Effort S.

### Errors, empty and waiting states

**F14. Argument errors use internal names and never offer help.** Sev 2. `error-responses`
rule 6; `command-line-interfaces` rules 1 and 10. [Contract] (P5 genopt lines).
Evidence (`OUT/noDrive.txt`, all exit 64):
```
Error parsing "abc" as a int32_t for argument "offset"
Error parsing -1 for argument "retries": not in [0:2147483647] range!
Error parsing 0 for argument "reread_time_limit": not in [1:2147483647] range!
Missing value for argument "--bitrate"
Invalid paranoia level 9 must be between 0 and 3!
Unable to parse command line argument: --bogus
Invalid format "mp9"
```
C types, variable names with underscores (the person typed `--reread-time-limit`) and
interval notation. "Missing value" uses the flag form, so the parser is inconsistent with
itself. No line says `Run cyanrip --help`, and `Invalid format "mp9"` doesn't mention `-o
help`. Fix: `--offset needs a whole number of samples, such as -s 6; got "abc".` Name the flag
as typed, add a closing `See cyanrip --help.`, and suggest the nearest option for an unknown
one. Effort M.

**F15. GNU forms refused, and the refusal looks like a secret.** Sev 2.
`command-line-interfaces` rule 1. [Contract] (P1 notes and Platterpus's argv builder;
accepting more forms adds behavior, removes none).
Evidence: `--device=../disc/basic.cue` → `Unable to parse command line argument:
--device=[withheld]`. The person's own device path is hidden as if it were a key, because
`--acoustid-key=` can't be told apart (`cyanrip_main.c:3095`). `-NAI` → refused. `... -- foo`
→ `Unable to parse command line argument: --`. Fix: accept `--name=value` (then only the
key's value needs withholding), grouping of switches, and `--`. Effort M; `genopt.h` is
upstream's, so carry it as a patch or offer it upstream.

**F16. A requested output that can't be written exits 0, and only at the end.** Sev 2.
`error-handling` (one meaning per exit code); clig.dev "fail fast". [Contract] (exit code).
Evidence: `cyanrip -d disc.cue -N -I --diagnostics /nonexistent/x.json` → exit 0. The only
complaint is `Couldn't open diagnostics path "/nonexistent/x.json" for writing!`, the one line
in the whole program written to stderr (`diagnostics.c:1172`), after the full output. On a real
rip that's 40 minutes later. Fix: open or create the path at start-up and refuse with 64
before reading; if writing fails at the end, exit non-zero. Effort S.

**F17. Late validation of track numbers.** Sev 1. Heuristic 5 (error prevention). [Safe].
`-l 9` on a 2-track disc prints 49 lines of disc information, then `Invalid rip index 9, list
has 2 tracks!` (exit 64). It needs the TOC, so it can't come first, but it can come before
the header. Effort S.

**F18. A naming-scheme typo is accepted silently.** Sev 2. Heuristic 5. [Safe] for a
warning, [Contract] for a refusal.
Evidence: `-D {albm}` writes into a folder named `albm/` (`OUT/rip5/o.txt`: `albm/1 - Unknown
track.flac`), with no warning. Fix: refuse an unknown `{tag}` and name the known ones; `-I`
already previews paths, which helps. Effort S.

**F19. Ctrl-C.** Sev 1, from the source. Heuristic 1. [Safe] (written by the signal handler,
not `cyanrip_log`). `cyanrip_main.c:2656` prints `Trying to quit`; a second Ctrl-C prints
`Force quitting` and `_exit(1)`s without the footer. Fix: `Stopping after this read; press
Ctrl-C again to quit at once (the log won't be finished).` Effort S.

**F20. Progress output.** Sev 2. `command-line-interfaces` rule 3; clig.dev "don't animate
when not a terminal". [Contract]: Platterpus parses the line, though P3 calls it unstable.
Lowering the rate keeps the wording, but announce it, since `redraw_run.py` counts redraws.
Evidence: `OUT/rip1.stdout`, one `\r`-joined line per track, 300 redraws for a 4-second track
(`Ripping and encoding track 1, progress - 0.33%, ETA - 1sRipping and ...`, a 15 KB line). At
75 frames a second of audio, a 74-minute disc is about 333,000 redraws, around 18 MB, in
anything that saves stdout. Platterpus notes they're "~98% of everything it prints"
(`redraw_run.py:5`). The ETA is `(frames_to_read - frames_read) * per-frame time`, which is
the whole rip, but it sits beside the track's own percentage. Fix: redraw at most 4 times a
second; when stdout isn't a terminal, print a line at each 10%. Later, in a round, `Track
3/14: 42% · disc 3m left`. Effort S for the rate.

**F21. Errors on stdout.** Sev 2 for scripts, 1 for people. `command-line-interfaces` rule 3.
[Contract]: Platterpus reads stdout only, so moving errors to stderr would hide them from it.
Evidence: `OUT/info.stderr` and `OUT/rip1.stderr` are empty; `cyanrip -J > disc.cue` gives a
file whose CUE sheet starts at line 42 (`OUT/rip5/j.out`). Fix, safe now: `-J` already writes
the `.cue` file, so say so in help ("writes the CUE sheet to the output folder") instead of
"print". Later, in a round: `-J -` to write only the sheet to stdout. Leave the error stream
alone unless Platterpus agrees to read stderr too. Effort S / M.

### Settings

**F22. The AcoustID key is a flag; the environment variable that avoids it isn't in help.**
Sev 2. `command-line-interfaces` rule 8. [Safe].
Evidence: help: `--acoustid-key: AcoustID user API key, to submit fingerprints of verified
rips`. `cyanrip_main.c:3136` reads `CYANRIP_ACOUSTID_KEY`, but neither help nor the README's
table says so. The fork already withholds the key from `Invoked as:`, which is good. Fix: in
help, "Prefer CYANRIP_ACOUSTID_KEY, or --acoustid-key-file PATH". Effort S.

**F23. No saved settings.** Sev 2. Heuristic 7. [Additive] (the header's `Offset:` line
already records the value used). The offset, preferred formats and naming schemes are retyped
on every rip. Fix: an environment variable for the offset at least (F3), or a small config
file; precedence by `coding/configuration`. Effort M.

### Files and safety

**F24. A re-rip silently overwrites the earlier rip.** Sev 2-3. `usability-review` "an
unguarded destructive action"; `command-line-interfaces` rule 7. [Safe] to refuse by default
with `--overwrite`? No: it's [Contract], because Platterpus may rely on re-running into a
folder. Ask in a round.
Evidence: `OUT/rip1`, a second identical run rewrote all four files at 01:31:11 (they were
01:27:21), including the FUN512-signed log, with no message. A person re-ripping a damaged
disc with `-Z` can lose a better earlier rip and its proof. Fix: if the album folder exists,
refuse and name `--overwrite`, or write to `Album (2)`. Effort M.

**F25. Album folders are created private (0700).** Sev 2. Heuristic 4. [Safe].
Evidence: `OUT/rip1/Unknown disc (ONPX) [FLAC]` is `drwx------` under umask 0022, from
`naming.c:974` `mkdir(ret, 0700)`, inherited from upstream (`origin/master:src/naming.c:466`).
The fork's own `--keep-every-read` uses 0755 (`cyanrip_main.c:1540`). A media server running as
another user (Jellyfin, Plex) can't read the library. Fix: 0777 and let the umask decide.
Effort S.

### Accessibility and keyboard

**F26. No quiet mode, and redraws flood screen readers.** Sev 2. `command-line-interfaces`
rule 7 (`-q`). [Additive]. With per-frame `\r` redraws (F20), a screen reader or a braille
display re-announces the line hundreds of times a second, and there's no `-q`. Fix: F20's rate
cap and a `-q` that keeps errors and the footer. Effort S.

### Performance a user feels

**F27. MusicBrainz retries wait silently.** Sev 1. Heuristic 1. [Safe]. In
`OUT/shots/unknown-disc.png`, `MusicBrainz query failed: 503 Service Unavailable` / `Retrying
in 15 seconds (attempt 2 out of 4)...` is good. Up to 45 s can pass with no further line, and
the message doesn't mention `-N` until the end. Fix: add "(skip with -N)" to the retry line.
Effort S.

### Docs a user reads

**F28. There's no man page;** `--help` and a 600-line README are all there is. Sev 1. [Safe].
Generate one from help with `help2man` at build time. Effort S. See also F4 and F12.

## 3. What's already good (keep it)

- **Exit codes have classes and are documented:** 64 for a refused argument, 74 for the disc
  or drive, 128+N for a signal, and `--verify-log`'s own 0-5 (`PROVIDER-CONTRACT.md` P4).
- **It never prompts,** and most refusals name the flag that gets past them (`-N`, `-s 0`,
  `-R`, `-c`).
- **The fork's own errors give the cause and the fix,** with numbers: `-Z 5 can never converge
  with -r 3: it needs 6 reads to agree, and -r 3 never allows that many. Use -r 6 or more!`
  Keep this; only the `!` goes.
- **`-I` works as a dry run:** it shows the folder, log and CUE paths and each track's file name
  without writing anything (`OUT/info.stdout`).
- **Machine form for the program:** `--diagnostics` JSON with a schema version (`OUT/rip5/ok.json`),
  and every logged value escaped so it can't forge a line. That's the right place for the
  parser to move to over time.
- **Secrets:** the AcoustID key is withheld from `Invoked as:` and the record.
- **The footer** (`Ripping errors`, `Encoder errors`, `Read stalls`, `Rip completed: yes (2 of
  2 tracks)`) is a clear verdict, written even after a signal.
- `--help`, `-h`, `--version`, `-v`, `-V`: stdout, exit 0, whatever else is on the line.
  `-o help` lists formats, folders and cover-art support.
- The fork's new options are long-only, so they don't collide with upstream's letters.

## 4. Lessons for our skills

1. **`command-line-interfaces`: when the people-format is already the parsed interface.**
   Rule 4 says the people-format "may change". Here the people-format is the contract, and
   rule 3 (errors and progress to stderr) would hide errors from the consumer. The module
   needs a rule and an audit row: "If a consumer parses human output, freeze it under a
   contract; add hint lines rather than reword; give the consumer a machine channel and move
   it there before changing the text." This was the review's hardest question, and the module
   gave no rule for it.
2. **`command-line-interfaces`: progress.** Nothing beyond "to stderr". Add: redraw at most a
   few times a second; when not a terminal, no `\r` animation (a line per milestone); a whole-job
   ETA labeled as such. Audit check: `prog > out.txt` and look at the size and line lengths.
   That check would have caught F20 and F26.
3. **`command-line-interfaces`: the audit table has no row for rule 1.** Add "Option syntax:
   `-abc`, `--name=value`, `--`" (F15). Also add a C row to the parser table (`getopt_long`,
   `argp`) and C's `argv` to "Hand-rolled parsing"; the table skips C, and this program
   hand-rolls its parser.
4. **`command-line-interfaces`: help readability.** Rule 2 is only about where help goes and
   its exit code. Add: a usage line and an example first; wrap to the terminal (80 when piped);
   no `(default: false)` noise; defaults printed as typed (`256`, not `256.000000`); a default
   the program then refuses is a bug (F3, F12).
5. **`coding/error-responses`: argument errors.** Add: name the option as the person typed it,
   never an internal variable or a C type; a usage error ends by pointing to `--help`; an
   unknown option suggests the nearest. Also add a tone rule, "no exclamation marks in errors",
   for the owner's "calm presentation"; neither this module nor `house-style` has one (F9, F14).
6. **`coding/error-responses`: routine conditions aren't errors.** "Not in the database",
   "skipped because you turned it off": say them as status, or not at all (F9).
7. **`command-line-interfaces`, or `coding/logging-and-observability`: third-party library
   messages.** No rule covers a linked library writing to the person's terminal (libcdio,
   FFmpeg's ebur128). Add: route library logs into the program's log, show them only under the
   program's own message, and never escape-encode text shown to a person (F1, F6).
8. **`coding/error-handling`: fail fast on outputs.** "Validate every output path before the
   long work; a requested artifact that wasn't written makes the exit non-zero" (F16). No
   module says it.
9. **`command-line-interfaces` rule 7: an overwrite is destructive.** The audit row "State
   changes" looks for a write with no dry run, not a re-run that replaces earlier results. Add
   "a re-run into an existing output silently replaces it" (F24).
10. **`usability-review`: file permissions as user experience.** Files or folders a program
    creates that other tools (media servers, backups) can't read; the module has no check. Add
    "created with an explicit mode instead of the umask" to the code-readable list (F25).
11. **`usability-review`: internal process vocabulary on screen.** Heuristic 2 covers it in
    principle, but nothing tells a reviewer to look for project-management state (round, lap,
    verdict, "NOT a released build") in output a person reads. Add an example to "labels"
    (F5).
12. **`usability-review` and `command-line-interfaces`: forks.** No rule on keeping a fork's
    additions in upstream's voice and length, or on README installation steps that install
    upstream instead of the fork (F4, F11). A sentence in `usability-review`'s consistency
    heuristic would do.
13. **Caught well:** `usability-review`'s "value shown before it's measured" (F7) and "labels
    disagree" (F10), rule 8 on secrets (F22), and rule 6 on prompts (passed). These worked as
    written.
