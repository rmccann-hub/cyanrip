## The answer first

is the C code that handles data the program doesn't control.** Two defects are reachable from
outside the machine and rated `BLOCKER`:

  naming scheme Platterpus uses.

## Findings

### Code: C (`coding` contract; no C module exists)

1. **`BLOCKER`: a cover image is freed twice.**
   - **Where:** `src/coverart.c:306` copies `AVCodecParameters` with `memcpy`, then
     `avformat_close_input` frees the `extradata` the copy still points to. `src/coverart.c:62`
     and `src/cyanrip_encode.c:1491` `memcpy` that struct into each output stream, and each
     `avformat_free_context` frees it again.
   - **How it's reached:** any cover image whose demuxer sets `extradata`, such as H.264 in MP4,
     HEIF or AVIF. One can come from `-C`, or from the Cover Art Archive over plain
     `http://coverartarchive.org` (`src/coverart.c:27`).
   - **Evidence:** I read all three copies. The subagent's ASan harness ran the same call
     sequence on a one-frame H.264 MP4 and got `attempting double-free` in
     `avformat_free_context`. I didn't run that harness myself.
   - **Upstream has it too:** `git show origin/master:src/coverart.c` holds the same line.
   - **Fix:** `avcodec_parameters_copy()` in all three places, and HTTPS for the Cover Art
     Archive. File it upstream (`docs/upstream/defect-reports.md` has no entry for it).
2. **`BLOCKER`: metadata can climb out of the output directory, or make an absolute path.**
   - **The gap:** `crip_bprint_sanitize` in `src/naming.c` replaces `/` but lets `..` through,
     and `crip_trim_path_components` turns a component that is only spaces into an empty one.
   - **What the subagent got:** with `-D {album_artist}/{album}`, which a comment in
     `src/naming.c` (lines 166-186) records as Platterpus's scheme, artist and album `..` gave
     `../../…`, and an artist of three spaces gave `/X/X.log`.
   - **Sources of the metadata:** CD-TEXT from the disc, or MusicBrainz, whose installed
     libmusicbrainz5 5.1.0 the subagent found has no TLS.
   - **Evidence:** `grep -n '\.\.' src/naming.c` found no guard. The demonstration was the
     subagent's harness around the real `src/naming.c`; I didn't repeat it.
   - **Upstream has it too:** both functions are in upstream's `naming.c`.
   - **Fix:** refuse `.` and `..`, and empty components after trimming, in one sanitizer; add an
     image scenario with a hostile CD-TEXT album artist.
3. **`GAP`: the cover-art array can be written past its end.**
   - **Where:** `src/cyanrip_main.c:3070-3071` (`dst = &cover_arts[nb_cover_arts++]; if
     (nb_cover_arts > 31)`) accepts 31 user cover arts into `CRIPArt cover_arts[32]`
     (`src/cyanrip_main.h:523`). `src/coverart.c:403-418` then writes Front at `[31]` and Back
     at `[32]`, with no bound.
   - **How it's reached:** command-line arguments only, plus a MusicBrainz release.
   - **Upstream has it too.**
   - **Fix:** check `nb_cover_arts + 2 <= FF_ARRAY_ELEMS` before each database fetch.
4. **`GAP`: CUE lines can be injected.**
   - **Where:** `src/cue_writer.c:194` prints `FILE "%s"` with the path from `crip_get_path`,
     which nothing escapes. `cue_str` (`src/cue_writer.c:56-79`) replaces only `"`, `\n` and
     `\r`, so `\v`, `\f`, U+0085 and U+2028/2029 pass. Those are the characters
     `src/log_escape.c` exists to stop in the log.
   - **What the subagent got:** a title with `\n` wrote `TRACK 09 AUDIO…` at column 0 of the
     sheet, using the binary. The existing quotes test (`tests/rip_images.py:1816-1822`) inspects
     only `TITLE` and `PERFORMER`, so it never sees the broken `FILE` line.
   - **Upstream has `cue_str` too.**
   - **Fix:** one escape for every CUE string, sharing `log_escape.c`'s set. This changes CUE
     text, so it needs a handshake round first.
5. **`GAP`: a failed log, CUE or diagnostics write is reported as success.**
   - **Where:** `grep -c ferror` is 0 in `src/cyanrip_log.c`, `src/cue_writer.c` and
     `src/diagnostics.c`. `fwrite` at `src/cyanrip_log.c:1506` and `fclose` at
     `src/cue_writer.c:255` go unchecked.
   - **What the subagent got:** with the log linked to `/dev/full`, the rip exited 0 and printed
     `Rip completed:  yes`.
   - **Why it matters here:** it breaks the coding contract's rule 4 ("never report success for
     work that didn't happen"), and this repository's own first rule.
   - **Fix:** check `fflush`, `ferror` and `fclose`, and exit non-zero with a line at column 0.
     Exit codes are handshake material.
6. **`GAP`: the AcoustID secret is written into every log.**
   - **Where:** `record_invocation` (`src/cyanrip_main.c:2390-2405`) copies argv verbatim into
     `Invoked as:` and the diagnostics JSON, `--acoustid-key` included.
   - **Why it matters here:** logs are filed to the public `evidence` branch, and
     `tools/redact.py` has no rule for the key (`grep -n -i acoustid tools/redact.py`: none).
   - **What I searched:** `git grep -i acoustid-key -- tests/fixtures` found no key in the
     default branch's fixtures. I didn't search the evidence branch, which this repository keeps
     out of fetches.
   - **Fix:** print the key as `<redacted>` in `Invoked as:` (a log-text change, so a round),
     and read it from an environment variable.
7. **`GAP`: a packet-write error is lost.**
   - **Where:** `src/coverart.c:87-90` writes the packet, frees it, then calls
     `av_interleaved_write_frame(avf, pkt)` again with `NULL`, which overwrites the first error.
   - **Upstream has it too.**
   - **Fix:** test the first call's result, and drop the second call or make it an explicit
     flush.
8. **`DRIFT`: some local files are treated as URLs.**
   - **Where:** `string_is_url` (`src/coverart.c:360-368`) compares only 4 characters for every
     scheme, so `httpd.jpg` and `ftps-art.png` count as URLs.
   - **Upstream has it too.**
   - **Fix:** compare `strlen(scheme)` characters.

### Code: Python and shell (`coding`: python-security, python-coding, bash-coding)

9. **`BLOCKER`: archive member names escape `--into`.**

     file confines it: `grep -n 'is_relative_to\|resolve()\|"\.\."'` finds only line 617, which
     resolves `dest` itself.
   - **What's at risk:** a member named `../../x.md`, or an absolute path, is written outside the

     reachable. The bundles come from the owner's own Platterpus export, which lowers the
     likelihood but not the rating.

13. **`GAP`: `.github/mingw-build.sh` has no strict mode, and an unguarded delete.**

    - **The delete:** `cd "$CYANRIPBUILDDIR" && rm -rf "$vcsFolder"` (:63-64) has no `:?`, and
      `cd ""` succeeds in bash. The values are constants in the file today.
    - **An empty array:** with nothing in it, :93-96 still runs `mv -f '' '.dyn'`.
    - **Fix:** `set -euo pipefail`, `"${vcsFolder:?}"`, and a guard on the empty array.
