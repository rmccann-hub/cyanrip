## Findings

Most severe first. "Reproduced" means shown on a build of this commit; "read" means from the
code alone.

### BLOCKER

1. **The log is cut short on a full disk, and the rip still reports success.** c-coding,
   *Unchecked writes*. `src/cyanrip_log.c` writes the log with `fwrite` at lines 1471, 1506 and
   1582 and `fprintf` at 1399, and closes it with `fclose` at 1401, checking none of them, nor
   `stdout` at 1592-1593. Reproduced: with `-L` pointing the log at a 4 KiB `tmpfs`, the log
   stopped at exactly 4096 bytes, mid-line (`Sample pe`), with no footer and no `Log FUN512:`
   line. The audio was complete, cyanrip exited 0, and stdout carried no error. Unrecorded:
   `docs/SETTLED.md:132` covers a full disk under the audio files, not the log. The log is this
   program's archival product, which is why the row rates it `BLOCKER`. Fix: check each write
   and `fclose` (or `ferror` before `fclose`), keep the first `errno`, report it on stderr at
   column 0, and exit non-zero.
2. **The CUE sheet is empty on a full disk, and the rip still reports success.** c-coding,
   *Unchecked writes*. `src/cue_writer.c:108` and the `CLOG` macro's `fprintf` calls are
   unchecked, and so is `fclose` at line 256. Reproduced: with `-M` on a full `tmpfs`, the sheet
   was 0 bytes, exit 0, and no message. Fix: as for finding 1.
3. **The diagnostics record's write and close are unchecked.** c-coding, *Unchecked writes*.
   `src/diagnostics.c:907-908`: `fwrite(b.str, 1, b.len, f); fclose(f);`. The open failure at
   line 896 is reported, but a short write isn't. The record is read by the consumer. Read, not
   reproduced. Fix: check both and print the same column-0 stderr line the open failure prints.
4. **The AcoustID user API key is taken in `argv` and written into every log.** c-security,
   *Secrets*. `--acoustid-key` (`src/cyanrip_main.c:2711`) is a per-user credential. Any local
   user can read it from `/proc/<pid>/cmdline`. `record_invocation()`
   (`src/cyanrip_main.c:2390-2406`) copies argv whole, and the copy is logged as
   `Invoked as:` (`src/cyanrip_log.c:960`) and stored in the diagnostics JSON
   (`src/diagnostics.c:654`). Reproduced with the placeholder `CHANGEME-USER-KEY`: it appeared
   on log line 2 and on stdout. Logs are filed as evidence and shared with the consumer. Fix:
   read the key from a file or the environment, and replace its value in the recorded
   invocation with a marker such as `<redacted>`.
5. **A tag value of `..` puts the rip outside its folder.** c-security, *Paths*. Already
   recorded in `docs/KNOWN-ISSUES.md:290`, with a fix proposed to the consumer first.
   `crip_bprint_sanitize()` (`src/naming.c:151-220`) replaces `< > : | ? * / \ "` and invalid
   UTF-8, but not a component that is exactly `.` or `..`, and doesn't handle a leading dot or
   control bytes. MusicBrainz, CD-TEXT and `-a` all feed it. Re-measured at this commit:
   `-D <root>/{album_artist}/{album} -a album=..:album_artist=..` wrote `1.flac`, `2.flac`,
   `log.log` and `sheet.cue` two levels above `<root>`, exit 0. Fix: as the record proposes,
   map a whole `.` or `..` component, and control bytes, to a safe name in every `-T` mode.
6. **AccurateRip and the Cover Art Archive are fetched over plain HTTP, and libcurl's protocols
   aren't limited.** c-security, *Secrets, transport*. `src/accurip.c:26`
   (`http://www.accuraterip.com/accuraterip`) and `src/coverart.c:27`
   (`http://coverartarchive.org/release`); both are on by default, turned off by `-A` and `-U`.
   An on-path attacker can forge the AccurateRip entries the log reports as a match, and can
   supply the image bytes cyanrip embeds into the output files. No `CURLOPT_PROTOCOLS_STR` or
   `CURLOPT_REDIR_PROTOCOLS_STR` is set anywhere in `src/`, and `src/coverart.c:193` follows
   redirects. Both endpoints are documented in `docs/DEPENDENCIES.md:75,77`, but not as a
   defect. Read from the code. Through this session's HTTPS proxy, `https://coverartarchive.org/release/<id>`
   answered 307 to an `https://archive.org` URL and `https://www.accuraterip.com/accuraterip/`
   answered 200. Whether accuraterip.com serves its `dBAR` files over HTTPS with a valid
   certificate needs a check off this proxy. Fix: `https://` for both, and set both protocol
   options to `"https"`. If AccurateRip has no working HTTPS, record that and say so in the log.
7. **A unit test passes when its discriminating case can't run.** c-coding, *Unprobed tests*.
   `tests/fun512.c:133-147`: when `/tmp/cyanrip-fun512-oversize.log` can't be created, the test
   prints `UNPROBED: ... oversize case not run` and goes on to return 0. The comment at lines
   128-131 calls this "the discriminating case", the one that fails a revert in every build.
   Reproduced by making that path a directory: `UNPROBED ...`, then `all checks passed`,
   exit 0. Fix: `return 77` when the case can't run, or create the file with `mkstemp` so it
   always can (see finding 21).

### DRIFT

8. **`meson_version` is below the features used.** c-build, *Floor*. `meson.build:22` says
   `>=0.53.0`. Meson 1.3.2 reports features from 0.55 (string concatenation in
   `meson_options.txt:15-16`), 0.56 (`meson.project_source_root()` at `src/meson.build:70,128`
   and `tests/meson.build:521`) and 0.62 (`dependency('dl')` at `tests/meson.build:253,262,271`).
   `docs/DEPENDENCIES.md:35` repeats `>=0.53.0`. No CI job builds with the floor. Reproduced
   (Meson's own warning at setup). Fix: raise it to `>=0.62.0`, or lower the features, and add a
   CI job pinned to that Meson.
9. **The build names C99 but uses C11's `<stdatomic.h>`.** c-coding, *Standard*.
   `meson.build:3` sets `c_std=c99`; `src/cyanrip_encode.c:21,62-63` include `<stdatomic.h>` and
   declare `atomic_int`. `src/meson.build:2` adds `-D_ISOC11_SOURCE -U__STRICT_ANSI__`. The
   mismatch was read from the code. The compilers don't flag it: GCC 13.3 and Clang 18.1 at
   `-std=c99 -pedantic` both compiled an `atomic_int` with no diagnostic (reproduced). Fix: set
   `c_std=gnu17,c17` (Meson 1.3 or later; see finding 8) or `c11`, and drop `-U__STRICT_ANSI__`
   if nothing then needs it.
10. **The warning gate reads `build/` and not the build under test.** c-build, *Warning gate*.
    The gate exists and is sound: `tools/warn-gate.py` re-runs every `src/` unit under the
    shipped flags with colour off, and fails on any diagnostic. But `tests/meson.build:304-307`
    registers it without `--build`, and its default is `"build"` (`tools/warn-gate.py:116`).
    Under any other build directory it fails, or it gates a different configuration's flags.
    Reproduced: `Compiler diagnostics` failed with `no .../build/compile_commands.json`.
    `tools/warn-gate.py --build <this build>` reported `0 diagnostic(s)` in 23 units and
    exited 0. CI happens to use `build`. The same assumption fails two `Settled facts` rows here
    (`./build/src/cyanrip: not found`); that is a records check outside this audit's scope.
    Fix: pass `'--build', meson.project_build_root()` in the `test()` args.

### GAP

11. **The project asks for no hardening flags.** c-build, *Hardening*. `src/meson.build:1-18` has
    warnings only. Reproduced: no `-fstack-protector`, `_FORTIFY_SOURCE` or `-z relro/now`
    appears in `compile_commands.json`. The Ubuntu binary is still hardened (`readelf`: `DYN`,
    `BIND_NOW`, `GNU_RELRO`; four `__*_chk` symbols), but only because Ubuntu's GCC adds those
    flags. The macOS Clang and MinGW builds CI makes get none of this. Fix: the module's flag
    set, filtered by `cc.get_supported_arguments`, with `_FORTIFY_SOURCE=3` only at `-O1` or
    above and without sanitizers.
12. **No static analyzer runs in CI.** c-build, rule 7. `.github/workflows/ci.yml` runs none.
    GCC 13 `-fanalyzer` over `src/` found 5 warnings, all false positives (see `checked_ok`).
    Fix: an `-fanalyzer` or `scan-build --status-bugs` job that fails on a finding.
13. **No parser of outside data is fuzzed.** c-build, *Fuzzing*. `crip_json_get()` and
    `crip_json_str()` (`src/json.c`) parse network JSON; `crip_parse_accurip()`
    (`src/accurip.c:155`) parses AccurateRip's binary response; `cyanrip_verify_log()`
    (`src/fun512.c:57`) parses any file given to `-Y`. There is no fuzz target or `fuzzing`
    option. `tests/json.c` and `tests/arresp.c` cover chosen cases. Fix: a libFuzzer target per
    parser behind a `fuzzing` option, built with Clang.
14. **CI runs no Valgrind or ThreadSanitizer job.** c-build, rule 5 and *Run-time checks*. The
    program is threaded (encoder threads, the stall watchdog, `atomic_int` flags), and
    ASan+UBSan finds neither uninitialized reads nor races. Both ran clean here (see *What was
    run*). Fix: `add_test_setup('valgrind', exe_wrapper: ['valgrind', '--error-exitcode=1'])`
    and a `-Db_sanitize=thread` CI row.
15. **A cover art download has no size limit, and two allocations are unchecked.**
    c-security, rule 3. `receive_image()` (`src/coverart.c:126-140`) grows `art->data` for every
    byte the server sends, until the 60 s timeout. `src/coverart.c:264` then allocates a
    base64 copy about a third larger with `av_mallocz` and writes into it without a NULL check.
    No `CURLOPT_MAXFILESIZE` is set. Read. Fix: cap the size, for example with
    `CURLOPT_MAXFILESIZE_LARGE` plus a check in the callback, and check the allocation.
16. **Three hand-parsed numeric options accept trailing junk, and `-P` accepts no digits at
    all.** c-security, *Numbers, sizes*. `strtoll(..., NULL, 10)` with the end pointer
    discarded: `-P` at `src/cyanrip_main.c:2838`, `-c` at 2896 and 2904, `-p` at 2989.
    Reproduced: `-P abc` ran at `Paranoia level: none`, exit 0, so a typo silently turns error
    correction off. `-P 3x` ran at `max`, and `-c 2junk/3` tagged disc 2. genopt's own parsers
    check correctly (see `checked_ok`). Rated `GAP` rather than the row's `BLOCKER`: it is not
    memory safety (see the skill feedback). Fix: require the end pointer at `'\0'` and at least
    one digit, as `GEN_OPT_PARSE_UINT` does.
17. **A re-rip empties the existing log and CUE sheet before reading the disc.** c-coding,
    *In-place rewrites*. `src/cyanrip_log.c:1339` and `src/cue_writer.c:32` open with `"wb+"`.
    Reproduced: re-running into the same folder replaced `log.log` (MD5 `985ad9ee…` became
    `0702b7c7…`), exit 0, with no message. A second rip that fails or is interrupted therefore
    destroys the first rip's attested log. The consumer has its own overwrite guard
    (`docs/KNOWN-ISSUES.md:312-314`), but other callers don't. Fix: write to a temporary file
    in the same folder and `rename` it at the end, or refuse an existing log unless asked.
18. **`p = av_realloc(p, n)` with no NULL check.** c-coding, *Undefined behavior* and its
    *Mistakes*. `src/accurip.c:206-211` assigns the result straight to `t->ar_db_entries` and
    then writes through it, so a failed allocation is a NULL write at an offset set by the
    server's entry count. The file's own comment at line 87 explains why `receive_data()`
    doesn't do this. `src/cyanrip_main.c:1906` checks for NULL but leaks the old block. Other
    unchecked allocations: `src/naming.c:72` (`av_mallocz` then `memcpy`), `src/cue_writer.c:104`
    (`av_strdup` then indexed) and finding 15. Read. All need an allocation failure, hence `GAP`.
    Fix: assign to a temporary and check every allocation.
19. **The build doesn't ask for `-Wformat=2`.** c-security, *Formats*. `src/meson.build:17` has
    `-Werror=format` and `-Werror=format-extra-args` but not `-Wformat-nonliteral`. The probe
    found no non-literal format at any call site; its only hits are `src/log_escape.c:267-301`,
    which rebuilds a bounded spec (`char spec[48]`, at most 35 bytes) from a format already
    checked by `av_printf_format`. Fix: add `-Wformat=2`, and suppress `-Wformat-nonliteral` in
    `log_escape.c` alone, with a comment saying what was checked.
20. **`sprintf` and `strcpy` or `strcat` remain.** c-security, *Copies*. `src/accurip.c:261`
    and `src/coverart.c:159` `sprintf` a compile-time version string into 256 bytes;
    `tests/genopt.c:55,60` and `tests/json.c:115-118` use `strcpy` and `strcat` on fixed test
    data. All are bounded by construction and none is reachable from outside. Fix: `snprintf`
    in `src/`.
21. **A test uses a fixed `/tmp` name.** c-security, *Temporary files*. `tests/fun512.c:133`
    writes `/tmp/cyanrip-fun512-oversize.log`. Two suites on one machine, such as two build
    directories, share it, and another user can occupy it, which leads to finding 7. The same
    file uses `mkstemp` at line 50. Fix: `mkstemp`.
22. **The `src` flags are added with `add_global_arguments`.** c-build, rule 2.
    `src/meson.build:168`. No effect today, since there are no subprojects, but a wrap added
    later would inherit `-D_XOPEN_SOURCE=700 -U__STRICT_ANSI__` and the `-Werror=` set. Fix:
    `add_project_arguments`, called from the root `meson.build` before `subdir('src')`.
23. **No memory-safety roadmap.** c-security, *Roadmap*. cyanrip is shipped C parsing network
    responses, disc images and logs, and the repository has no such document. Fix: a dated
    page naming the parsers, what guards each, and whether each could move.
